FLUJO DE PROCESAMIENTO (Pipeline de Detección):

1. CAPTURA
   Cámara → OpenCV.read() → Imagen BGR

2. DETECCIÓN DE VEHÍCULOS
   Imagen → DetectorPlacas.detectar_camiones()
         → Modelo YOLO (best_truck.pt)
         → Cajas de vehículos [(x1,y1,x2,y2), ...]
         → Tiempo: ~900ms

3. GENERACIÓN DE REGIONES
   Cajas vehículos → DetectorPlacas.generar_regiones_busqueda()
                  → Regiones optimizadas alrededor de vehículos

4. DETECCIÓN DE PLACAS
   Regiones → DetectorPlacas.detectar_placas_en_region()
           → Modelo YOLO (best.pt)
           → Cajas de placas [(x1,y1,x2,y2), confianza, ...]
           → Tiempo: ~850ms

5. RECONOCIMIENTO OCR
   Placa recortada → MotorOCR.extraer_texto()
                  → PaddleOCR (Python 3.13 subprocess)
                  → Texto crudo
                  → Tiempo: ~2s (después de warmup)

6. VALIDACIÓN
   Texto → text_utils.limpiar_texto() → Solo A-Z, 0-9
        → text_utils.es_placa_valida() → Regex validation
        → Filtros: países, años, longitud
        → Texto validado

7. PERSISTENCIA
   Placa validada → API REST POST /api/registros/entrada
                 → database/logs_entrada_salida.json
                 → WebSocket broadcast a clientes conectados

8. PRESENTACIÓN
   Dashboard React ← WebSocket (nueva_deteccion event)
                  ← REST API GET /api/registros/historial
                  → Actualización automática de UI

7. Obstáculos / Retos Técnicos / Aprendizajes

OBSTÁCULOS Y SOLUCIONES:

1. **Incompatibilidad de PaddleOCR con Python 3.14**

   Problema: PaddleOCR no tiene builds oficiales para Python 3.14, causando errores de importación.

   Solución: Implementé un sistema dual de entornos virtuales:
   - venv/ con Python 3.14 para el sistema principal (YOLO, FastAPI, etc.)
   - venv_old_3.13/ con Python 3.13 exclusivamente para PaddleOCR
   - Creé ocr_wrapper.py que ejecuta PaddleOCR en subprocess usando el entorno 3.13

   Aprendizaje: La importancia de la compatibilidad de dependencias y cómo usar subprocess para aislar componentes con requisitos conflictivos.

2. **Detección de texto basura en placas (años, países)**

   Problema: PaddleOCR detectaba correctamente el texto, pero incluía palabras como "GUATEMALA", "CENTROAMERICA", "2024", etc., junto con la placa real.

   Solución: Implementé un sistema robusto de validación en utils/text_utils.py:
   - Lista de palabras clave a filtrar (países, regiones)
   - Regex para detectar años solos (4 dígitos consecutivos)
   - Validación de longitud (4-10 caracteres)
   - Validación de formato (letras+números o 5+ números)
   - Deduplicación de subcadenas

   Aprendizaje: La importancia del post-procesamiento en sistemas de IA. Los modelos son precisos, pero necesitan lógica de negocio para filtrar resultados.

3. **Conversión de tensores PyTorch a NumPy**

   Problema: YOLO retorna resultados como tensores PyTorch, pero OpenCV requiere numpy arrays. Conversiones directas causaban errores de tipo y memoria.

   Solución: Creé utils/image_utils.py con función convertir_a_numpy() que:
   - Verifica si es tensor PyTorch (.is_cuda, .device)
   - Mueve a CPU si está en GPU (.cpu())
   - Convierte a numpy (.numpy())
   - Valida dimensiones esperadas
   - Convierte tipos de datos correctamente (float32 → uint8)

   Aprendizaje: La importancia de manejar diferentes abstracciones de datos en el stack de ML (tensors vs arrays).

4. **Optimización de detección de placas en imágenes grandes**

   Problema: Procesar imágenes completas con YOLO era lento (~5-7 segundos) y detectaba muchas regiones irrelevantes.

   Solución: Implementé detección en dos etapas:
   1. Detectar vehículos primero con best_truck.pt
   2. Generar regiones de búsqueda solo alrededor de vehículos
   3. Detectar placas únicamente en esas regiones

   Resultado: Reducción del tiempo de procesamiento a 3-4 segundos y mejora de precisión al eliminar falsos positivos.

   Aprendizaje: A veces más etapas de procesamiento pueden ser más rápidas que una sola etapa global, especialmente cuando se puede reducir el espacio de búsqueda.

5. **Cooldown para evitar registros duplicados en cámara continua**

   Problema: La cámara detectaba la misma placa múltiples veces en segundos consecutivos, generando cientos de registros duplicados.

   Solución: Implementé un sistema de cooldown en camera_garita.py:
   - Diccionario {placa: timestamp_última_detección}
   - Verificación: solo registrar si han pasado >30 segundos
   - Limpieza automática de entradas antiguas (>5 minutos)

   Aprendizaje: Los sistemas en tiempo real necesitan lógica de estado para evitar duplicación de eventos.

6. **Mejora de OCR en placas pequeñas o de baja resolución**

   Problema: PaddleOCR tenía baja confianza (<70%) en placas pequeñas (ancho <100px).

   Solución: Implementé redimensionamiento automático en utils/image_utils.py:
   - Detectar si placa tiene ancho <150px
   - Redimensionar proporcionalmente a ancho mínimo 200px
   - Aplicar filtro de suavizado para mejorar calidad

   Resultado: Mejora de confianza OCR en 15-20% para placas pequeñas.

   Aprendizaje: El pre-procesamiento de imágenes es crítico para mejorar resultados de modelos de ML.

7. **WebSocket: Manejo de múltiples clientes conectados**

   Problema: Al tener múltiples pestañas del dashboard abiertas, las notificaciones solo llegaban al primer cliente.

   Solución: Implementé un sistema de broadcast en api_dashboard.py:
   - Lista active_connections = [] para trackear clientes
   - Método broadcast() que itera sobre todos los clientes
   - Manejo de excepciones para remover clientes desconectados

   Aprendizaje: WebSocket requiere manejo explícito de múltiples conexiones concurrentes.

8. **CORS en desarrollo con frontend separado**

   Problema: El dashboard React (localhost:5173) no podía consumir la API (localhost:8001) por políticas CORS.

   Solución: Configuré CORS en api_dashboard.py con CORSMiddleware:
   - allow_origins=["*"] para desarrollo
   - allow_methods=["*"]
   - allow_headers=["*"]

   Nota: En producción se debe restringir a dominios específicos.

   Aprendizaje: La importancia de configurar CORS correctamente en arquitecturas frontend/backend separadas.
